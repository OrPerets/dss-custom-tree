# Organization workspace review — 7 September 2026

## Current plugin

The plugin has a standard Dataiku webapp (AngularJS 1.8.2, HTML and CSS), a Flask backend, and a reusable Python hierarchy service. It supports dataset validation, manager rules, reporting moves, snapshots, and CSV exports. The backend and plugin parameter contracts were retained for this UI revision.

## Findings and implemented changes

| Previous experience | Revised experience |
| --- | --- |
| Every employee card displayed ID, location, level, status, rules, warnings, capacity and readiness. | Cards prioritize name, role, department, and direct reports. A warning indicator remains visible where review is needed. |
| The entire hierarchy was fitted into a canvas narrowed by an automatically opened employee panel. | The initial view shows three reporting levels, with individual team expansion and explicit two-level/all-level choices. Details open on selection. |
| Search was hidden inside a filter menu. | Search is always visible and searches the full organization, including collapsed teams. Matching people appear with their reporting path. Clearing filters restores the chosen branch view. |
| Multiple metrics, repeated source labels and short labels such as “Tree”, “Moves”, “Sync” and “Cap” competed for attention. | One compact summary and one chart toolbar. Actions use “Save version”, “Changes & versions”, “Export”, and “Change manager”. The data source is inside version history. |
| A “LIVE” badge appeared whenever the workspace was loaded. | The header reports unsaved changes without implying that the organization is published or live. |
| The CSS contained 4,142 lines of overlapping styles and overrides. | One component stylesheet with shared color, typography and spacing tokens; restrained Amdocs plum/pink accents; subtle connectors; no gradient cards or decorative status badges. |
| Reporting changes depended on dragging. | Dragging is retained; employee details also offer a keyboard-accessible manager selector using the same validation and submission path. |
| Small screens shrank cards to an unreadable overview. | Narrow viewports start at a readable scale with touch panning. “Fit” remains available for an explicit full overview. |

## Verification

- 20 existing Python unit tests passed, including validation, moves, persistence and synthetic hierarchy scaling.
- 12 browser tests passed against the real Flask backend and bundled sample CSVs.
- Browser coverage: level selection, branch expansion/collapse, search into collapsed teams, empty results, department/review filters, details disclosure, keyboard activation and Escape focus restoration, accepted/rejected manager changes, saved-version reload, CSV content, HTML drag/drop events, touch panning, missing storage configuration, backend failure and retry.
- Responsive controls and dropdown bounds checked at 390, 768, 1024 and 1920 pixels; desktop rendering inspected at 1440 pixels. Mobile checks use Chromium emulation, not physical devices.
- JavaScript syntax and plugin structure checks passed. The plugin verifier retains one naming warning: the plugin ID `employee-org-tree-visualizer` differs from the checkout folder `dss-custom-tree`.
- No browser console errors were observed in the inspected local workspace.

## Local preview and scope

Run `python3 demo/serve.py` in an environment with Flask and pandas, then open `http://127.0.0.1:8765`. The preview uses the real frontend and backend with bundled sample records. Snapshots are isolated in a temporary directory and removed when the server stops. It does not connect to DSS.

This revision is local. DSS upload, embedded webapp verification, and acceptance against an Amdocs dataset have not been performed. Authentication, authorization, framework migration, and backend redesign are outside this UI revision.
